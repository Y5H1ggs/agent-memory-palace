# 语用层：一句话是什么行为

> 词法层解决「有哪些词」，语义层解决「和哪条像」，
> 但决定**该不该记、记成什么**的是第三层：这句话在做什么事。

同一串字，行为不同，对存储的要求完全相反：

| 说法 | 行为 | 强度 | 该怎么记 |
|---|---|---|---|
| 以后都别用表格了 | 禁令 | 0.90 | core（必须遵守） |
| 别用表格 | 禁令（弱） | 0.72 | fact（可协商） |
| 能不能别用表格 | **请求** | 0.55 | event（可以拒绝） |
| 表格是不是有点多 | 不满 / 暗示 | 0.35 | event + 标「未确认」 |
| 我上次说过别用表格 | **纠正** | 0.85 | event，重点不是表格，是「你没记住」 |
| 随便你 | **撤回沟通** | 0.25 | event，**绝不等于同意** |

`pragmatics.py` 做的就是这件事：分类、给强度、推动机，全部规则法、可解释、零依赖。

---

## 一、三条设计原则

### 1. 只标不猜到底

每个判断都带 `evidence`（命中了哪些原文）与 `confidence`。
低于 0.5 就退回 `statement` —— **宁可少判，不可错判成规则**。

```python
classify("以后都别用表格了")
# Speech(act='prohibition', force=0.9, motive='', hedged=False,
#        confidence=0.55, evidence=('以后都别',))
```

它指着原话说「因为这里写了『以后都别』」，而不是给你一个 0.87 的黑箱分数。

### 2. 强度是乘出来的，不是加的

```
force = 基础强度 × 模糊限定(0.6) × 强调(1.15) + 0.05
```

- 「以后都别用表格了」→ 0.90
- 「我觉得可能不要用表格」→ 0.90 × 0.6 = **0.54**

这两句**不该同 tier**。前者进 core，后者最多 event。一句「可能」变成永久规矩，
是这类系统最典型的过度服从。

### 3. 否定与模糊分开处理

- **否定**改的是命题（用 / 不用）；
- **模糊**改的是**承诺度**（我有多确定）。

混在一起就会把「我觉得可能不要」记成「不要」。
所以词法层保留否定词并 ×2 权重（见 `LEXICON.md`），语用层单独标记 `hedged`。

---

## 二、为什么「撤回」必须单独一类

这是整套设计里最关键的一条，也是最容易被写错的一条。

```
用户：表格是不是有点多
你  ：那我改成表格 + 要点列表？
用户：随便你
```

把「随便你」记成「用户同意用表格」，系统就拿到了一张**从未发出的许可**。
用户实际表达的是「我不想再讨论这件事了」。

所以：

- `act=withdrawal`
- `is_preference() == False`（撤回、提问、暗示、抱怨、纠正都不算稳定偏好）
- `suggested_tier() == 'event'`（记下来，但不作为规则）
- `motive='放弃沟通（不等于同意）'`

注入时它会显示成 `（撤回（不等于同意））`，模型看到这个标记就不会把它当指令执行。

### 纠正也是同一类陷阱

「我上次说过别用表格」的主要内容**不是**「别用表格」，是「你没记住」。
如果只记成一条「用户偏好表格」，那条不满就被消解成中性偏好 —— 下次还会犯。

所以 `correction` 也不算 `is_preference()`，它的价值在于触发 `outcome contradicted`，
而不是写一条新偏好。

## 三、层级建议：两级衰减

不是按行为查表就完，还要看强度：

```
prohibition/directive  force >= 0.8  → core
                       force <  0.8  → fact（可协商）
hedged 且为 fact                     → event（记下来，别当规矩）
暗示 / 撤回 / 提问 / 不满             → event
```

调用方永远可以覆盖：`remember(..., tier="core")` 优先。
`auto_tier=True` 只是「让系统按语用判断建议一个层级」，不是「自动立法」。

---

## 四、场景（register）

同一句话在不同场合分量不同：复盘里说「不该追高」是教训（fact），
闲聊里说是感慨（event）。

`detect_register()` 只认几个显式场景（review / execution / coding），
**看不出就老实返回 chat，不硬猜**。场景目前只作为元数据 + 面板展示，
还没有参与检索加权——那需要先有评测集来证明加权是对的。

---

## 五、边界（规则法做不到的）

1. **反讽与反问**：「你可真行」在规则法里是陈述句。这类只能靠模型，且模型也会错。
2. **上下文指代**：「那个改一下」——「那个」指什么，规则法无从判断。
3. **跨句意图**：「表格太多了。而且风险提示也没有。」两句话是一个整体诉求。
4. **未登录说法**：词表外的表达会退回 `statement`，标注「推断」而非「识别」。

所以这一层的定位是：**把显式标记抓准，抓不准就承认**。
它不是「理解用户」，是「不让明显的信号被丢掉」。

## 六、这次是怎么被验证的

```bash
python tests/test_pragmatics.py        # 26 项，重点是「撤回≠同意」与「模糊降级」
python tools/greenlight_audit.py       # 12 个变异，故意弄坏实现，看断言会不会红
```

绿灯审计第一次跑就抓到一个**假绿**：

> 原本有一条断言叫「合并时更硬的那次覆盖更软的」，用的是
> 「用表格呈现」vs「以后都别用表格了」—— 这两句余弦不够、长度比也不够，
> **实际根本没走合并路径**，是新建了一条。断言却绿了。

改成两句**文本完全相同**、只换 `speech` 对象之后，变异 `speech-force-kept`
立刻被抓。这也是这一整套工具存在的理由：
**断言全绿只证明「我写的断言在本实现下成立」，不证明它在守任何东西。**
