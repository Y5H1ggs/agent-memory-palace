# 词法层：一切语义的地基

> 这一层的错误不会报错，只会让上面每个机制**安静地说错话**：
> 检索召回不到、沉淀把无关的两件事写成一条结论、弃答线在你没想到的地方误判。

`memory_palace/lexicon.py` 只有三百来行，但它决定了 `semantics` 能看见什么。
在它之前，字符维是「每对字符等权加一，哈希进 64 个桶」——
于是 `输出`（满语料都是）和 `凯利`（只出现两次）权重相同。

---

## 一、四个决定，每个都有具体代价

### 1. 归一：同一个词不该有两种写法

```python
normalize("ＵＴＦ－８ 编码")  # → "utf-8 编码"
```

NFKC（全角→半角）+ 小写 + 压空白。技术记忆里这类差异极多：
`UTF-8` / `utf-8` / `ＵＴＦ－８`、`PNPM` / `pnpm`。
不归一，等于同一个概念在向量里占三个格子，每个都弱三分。

### 2. 分词：中文双字 + 英文标识符

| 输入 | 切出 | 为什么 |
|---|---|---|
| `部署前先跑迁移` | 部署 / 署前 / 前先 / 先跑 / 跑迁 / 迁移 | 双字能表达「部署」「迁移」，不需要分词器 |
| `env.sh 要先 source` | `env.sh` + `env` + `sh` + `source` | 标识符整体保留，部件也保留 |
| `这件事的处理是好的` | 事的 / 件事 / 处理 / … | 单字 `的/了/是` 被丢掉 |

代价写在注释里：没有分词器，`工程师` 会被切成 `工程` + `程师`。
双字是零依赖下的最优折中，不是最优解。

### 3. 否定词：唯一保留的单字

```
"不追高，缩量不参与"  vs  "追高，缩量参与"
余弦 = 0.359   （自身重复 = 1.000）
```

这一条最容易漏，后果最严重：**把结论说反**。
中文 bigram 对否定极不敏感（只差一个字），所以：
- 单字默认全丢，**只留 `不没无非别勿禁未莫`**；
- 否定词额外 ×2 权重；
- 代价是它们也会抬高「不」与「不」之间的相似度 —— 但比起说反，这个代价可以付。

### 4. IDF：到处都有的词，不该和只有这里才有的词一样重

```
weight = log((N+1)/(df+1)) + 1      # df 是「出现在多少条记忆里」
```

**这条是整次改造的核心。** 反事实（`tests/test_lexicon.py`）：

| | 「构建机输出乱码」vs「输出用表格」余弦 | 会聚成一类吗 |
|---|---|---|
| 关掉 IDF（所有词同权） | **0.783** | 会（错） |
| 打开 IDF | **0.448** | 不会（对） |

同时它**没有误伤真正同主题的**：「输出用表格」与「输出优先精简」仍然聚成一类
（都属输出风格，聚得对）。**该分的分开，该合的还合** —— 这才是 IDF 该有的样子。

#### IDF 里有两个反直觉的点

**① 未登录词的权重必须是 0，不是最高。**

直觉是「罕见的词最有信息量」，所以没见过就该给最大权重。但中文按 bigram 切，
跨词边界会切出大量从未出现过的碎片：`怎么处理` → `么处`、`码怎`。
给它们最高权重，查询向量就被噪声拉长，真正的共同词被 L2 归一化稀释，余弦整体变低。

0 才对：文档侧这些维度本来就是 0，查询侧给多少权重都不会命中，只会抬高自己的范数。

**② IDF 不落盘，每次从语料现算。**

快照里只存文本，权重是文本的函数。换一批记忆，权重自然跟着变，不会留下陈旧统计。
代价是每次重建要扫一遍全语料 —— 见下面的性能账。

## 二、性能账（不粉饰）

改造前后（`python -m memory_palace.bench`）：

| 指标 | 改造前 | 改造后 | 原因 |
|---|---|---|---|
| 200 条 `cycle` | 19 ms | **51 ms** | rebuild 要为全语料建 IDF |
| 1000 条 `cycle` | 202 ms | **561 ms** | 同上，且节点多时同步次数增加 |
| 查询（热） | 1.5 ms | **3.1 ms** | 字符维 64 → 256，余弦变长 4 倍 |
| 写入 | 0.053 ms/条 | 0.113 ms/条 | 分词 + 归一 |

> **0.9.2 更正**：上面这张表是 0.9.0 的账。0.9.2 做了稀疏向量、聚类早停、增量补建与校验合并之后，
> 同一台机器上 200 条 `cycle` 是 **17 ms**（比改造前的 19 ms 还快），1000 条 `cycle` **108 ms**，
> 热查询 **0.9 ms**。词法层引入的代价已经被后续优化收回，且不是在改语义的前提下收回的
> （见 `tests/test_audit.py` 的保序证明）。

做了三个缓存把损失压到这个量级（否则是 12 倍）：

1. **分词结果 LRU**：一次 rebuild 里同一段文本要被算两遍（IDF 统计一遍、向量编码一遍）；
2. **聚类预取向量**：原来 N² 对候选会触发 2N² 次 lookup，200 条就是 4 万次；
3. **维度从 64 提到 256**：不是性能优化，是**正确性修复** —— 64 个桶装几千个词项，
   碰撞会把无关文本拉近，这本身就是误聚的另一个来源。

如果仍然嫌慢：调小 `char_dim`，或用 `encoder=` 换外部 embedding
（embedding 侧不做 IDF，因为 embedding 自带语义空间）。

## 三、边界（做不到的，写清楚）

1. **同义改写仍然召回不到**。`"构建机输出乱码"` 与 `"CI 日志一堆问号"` 余弦 0.0 ——
   它们没有共同词项。这靠 IDF 救不了，只能靠 embedding（`encoder=`）。
2. **中文双字切分会制造假词**。`工程师` → `工程` + `程师`，`程师` 是噪声。
   语料足够大时 IDF 会把它压下去（它很少和别的词共现），但小语料下它会捣乱。
3. **停用词表是手工的**，只覆盖最常见的中文虚词。英文停用词没做 —— 技术文本里
   `the`/`of` 本来就少，不值得为它加一层。
4. **IDF 在小语料上不可靠**。少于 20 条记忆时，df 统计没有统计意义，
   此时 IDF 接近全 1，行为退化成「同权」。这是数学限制，不是实现问题。

## 四、怎么验证它还在工作

```bash
python tests/test_lexicon.py     # 16 项，含 IDF 的反事实
```

其中最关键的一条是反事实：**把 IDF 换成全 1，误聚必须回来**。
如果哪天有人「优化」掉了 IDF，这条会立刻变红 —— 而不是等到某天发现
记忆里多了一条把两件无关的事写在一起的「结论」。
