# 架构

这份文档只写「为什么这么排、这么算」，不重复 API。行为细节都在各模块的 docstring 里。

## 一、每轮代谢的次序，以及每一步为什么不能提前

```
风格结算 → 沉淀 → 拼命抓住（预算）→ 遗忘 → 自述 → 人格结算 → 反思 → 自修正
```

| 次序 | 不能调换的理由 |
|---|---|
| 沉淀早于遗忘 | 否则刚要结晶的碎片会先被 GC 扫走，沉淀永远等不到第 3 条同类 |
| 抓住早于遗忘 | 「抓住」抬高锚点，是留存的唯一主动动作；晚于 GC 就来不及救 |
| 遗忘早于自述 | 否则自述会讲到已经不在图里的东西，故事变成幽灵 |
| 自述早于人格结算 | 人格要读「这一轮讲了什么故事」来判断自己有没有变 |
| 反思最后（除自修正） | 才看得见本轮全部事件；反思读不到事件的报告都是猜的 |
| 自修正晚于反思 | 先验旧账（pending patch 的观察窗）再结新账，否则新修正叠在未验证的假设上 |

## 二、三条核心公式

**1. 幂等衰减**

```
effective_weight(now) = base_weight × exp(-Δ天 / stability)
stability             = tier_factor × kind_factor × (1 + 0.75·ln(1+访问次数) + 0.25·√访问跨度天) × 情绪加固
```

权重不是被反复改写的余额，而是「锚点 + 时间」的读数。GC 跑一次和一百次，期末逐位相同。
旧实现每天扣一点，遗忘速度取决于你多久扫一次 —— 这是所有记忆系统最容易踩的坑。

**2. 情绪的双刃**

```
salience(now)       = |valence| × (0.4 + 0.6·arousal)        # 会退潮
stability_bonus     = gain × (0.6·salience + 0.4·peak)       # 乘进稳定性，不乘进权重
fidelity(distortion)= 1 - distortion × peak_arousal          # 不随时间恢复
```

情绪如果加在权重上，只是「更亮」；加在稳定性上，改变的是**衰减速度** —— 这才是
「怎么抓都抓不住的东西偏偏最难忘」。代价必须同收：唤醒越高，编码越可能是被情绪改写过的。

**3. 价值判断**

```
importance = 1.0·强度 + 0.9·情绪余温 + 0.8·逻辑凭据 + 1.1·叙事地位
叙事地位   = max(累计次数×时间衰减 / cap, 热度×时间衰减)，cap 默认 8，半衰 21 天
```

线性加权、不做归一化：纯物理强度的节点 importance ≈ weight，与旧的 `forget_w` 口径可比；
其余三项是**加成**，不是互相摊薄。叙事地位会退潮，所以「讲过一次」不是终身爵位。

## 三、两套遗忘律

- **结论**（core / fact / event）按**价值**取舍：记得住但没价值，也可以主动放手。
- **碎片**（已沉淀的 trace）按**物理强度**退场：它已经把价值交出去了，剩下的只是溯源窗口。

如果对碎片也套价值门槛，结晶的当轮就会把自己的出处全部抹掉 —— 那不是有原则的遗忘，是失忆。

## 四、自述是投影，不是节点

`NarrativeEngine.compose()` 每次重新算：按重要性选谁进故事、按标签分章、按创建时间排叙事弧、
按最近访问选出「当下」那一章、给每一条标可靠度、算出连续性与单主题占比。
产出是一份 `NarrativeRevision`（带版本号），**不落成图里的节点**。

被讲进故事的条目获得叙事地位，这是「我怎么讲这个故事」反过来塑造「我记得住什么」的闭环。
但闭环必须能被观测到收窄：单主题占比过高就是回音室，要写进自述文本里，而不是自我陶醉。

## 五、人格四层

| 层 | 谁改 | 改动代价 |
|---|---|---|
| 基座 Foundation | 只有人，需 reason + force | 系统对基座只读 |
| 人格 Personality | 证据驱动，带惯性与包络硬夹 | 被 floor/ceiling 挡住时记账，不静默丢 |
| 人设 Persona | 用户定义、切换、回滚 | 单一生效；残留（suppress）显式声明 |
| 修订 Revision | 每次变更留 diff | 可回滚，回滚本身也是一次变更 |

漂移 = `(0.35·mean_delta + 0.65·peak_delta) × velocity`。只除以维度数会被稀释：
七维里一维从 0.55 改到 0.95 只算 0.057，会被误判成稳定。所以峰值占 0.65。

## 六、语义检索：可解释优先

三层叠加，每层都能说清自己贡献了多少：

1. **概念层**：手工**种子**（不是全量词典）+ 多义词按上下文分份额；
2. **学习层**：从语料长出新概念词，四条判据同时成立（df 区间 / ≥2 个不同锚点同篇 / 提升度 / 纯净度）；
3. **字面层**：中文字符 bigram 哈希，兜住未登录词。

向量只从 `content` 编码，`tags` 走独立通道 —— 这样「内容相关但标签不同」才能真正被召回，
也才能证明检索读的是语义而不是标签。索引状态是图内容的纯函数（blake2b 签名对齐），
所以跨进程恢复后逐条一致。

**注意**：这不是 embedding，是「可解释的概念投影」。它换来零依赖和可追问，代价是召回上限。

## 七、状态与持久化

- 快照含：config 逐字段、图（节点 + 边）、逻辑边、风格规则、事件、墓碑、自述史、人格四层、自修正账本。
- 原子写：同目录 tempfile → `json.dump` → `fsync` → `os.replace` → 目录 fsync（Windows 走 `FlushFileBuffers`）。
- 返回 `durable` 布尔：内容落盘但目录项没持久化，是要被告警的事实，不是可以吞掉的细节。
- 版本迁移：`SUPPORTED_STATE_VERSIONS` 显式列出可读版本，缺字段走默认值，未知字段/类型错误一律响亮拒绝。

## 八、被刻意拒绝的设计

| 诱惑 | 为什么不做 |
|---|---|
| 用「每天扣一点」实现衰减 | 非幂等，遗忘速度取决于 GC 频率 |
| 把「自我」写成节点 | 那等于说「我」会衰减、会被 GC 扫走 |
| 情绪直接加权重 | 只让记忆更亮，无法解释「为什么难忘」 |
| 反思直接改配置 | 系统自己改自己的账本，比遗忘失控更危险 |
| 自修正放开所有参数 | 改基座不是修正，是换人 |
| 用上一轮指标判当期修正 | 统计窗口横跨修正前后，结论必然是错的 |
| 把概念词典写成全集 | 多义词无法归属，语料一变就过时 |
